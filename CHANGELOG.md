# Changelog

All notable changes to Disk Watch are documented here. Entries under **Unreleased** describe changes proposed or merged since the last tagged release; they do not imply deployment to any host.

## Unreleased

### Added
- Use a validated 16-hex-digit `LU WWN Device Id:` / `WWN Device Id:` as a `wwn:<lowercase-hex>` cache ID only when an explicit SMART refresh exposes no serial (#23 partial). Offline mocks cover WWN formats, changed /dev paths, malformed WWNs and serial precedence. Cached reads never probe hardware; no new runtime dependencies, by-id discovery or USB standby safety claim. Existing serial-based history IDs are unchanged.
- Extend CI to Debian 12 and 13 with unprivileged, network-disabled, read-only Docker test containers and an executable temporary filesystem for offline failure-injection mocks; run Bash/POSIX syntax checks and all nine existing offline mocked suites. Docker is a CI-only tool on the Ubuntu runner, not a runtime dependency. The offline installer test mocks `journalctl` availability on minimal Debian images; container tests do not certify real Proxmox hardware, journal access or root-level rollback.
- Add a lightweight `status`/`disks`/`health`/`history`/`report` CLI (#27) backed by local SMART snapshots. Read-only operations do not query disks or create state. A live `smartctl -a` snapshot requires an explicit device and both `--refresh --wake-ok`, since USB disks may spin up. Snapshot fields include health, temperature, hours, sector counters, NVMe written-GB estimate, wear and coarse self-test status where available; unsupported values remain `unavailable`. Includes portable packaging, offline mocked NVMe/ATA tests and documentation. Does not schedule SMART tests or automatically log alerts.

- Run existing Bash syntax and eight unprivileged offline regression suites on pinned Ubuntu 22.04 and 24.04 GitHub Actions runners (rather than moving `ubuntu-latest`), with toolchain versions recorded. This expands CI compatibility coverage but does not validate Debian/Proxmox, hardware or live root rollback; no runtime dependency changes.
- Make locally built portable source archives byte-reproducible across build directories and umasks using normalized GNU tar/gzip metadata and file permissions; add an offline byte-comparison regression. GNU tar and gzip are build-only prerequisites, with no runtime change or published release.
- Add an opt-in offline restore rehearsal into a private, empty sandbox, re-verifying snapshot integrity and copied file contents/modes without touching installed paths, systemd or host state. This does not provide live rollback.
- Add a read-only recovery planner for verified pre-install snapshots: list four fixed paths to restore or review without copying, deleting, changing services or touching host state. This is not a root-level rollback or transactional update.
- Add a read-only pre-install snapshot verifier that checks private ownership/mode, completion marker, fixed-path present/absent manifests, symlinks and SHA-256 integrity before manual restore. It never writes host files or performs rollback; legacy snapshots without hashes are rejected.
- Add relative-path SHA-256 integrity manifests to newly created pre-install snapshots and verify them before marking a snapshot complete; `sha256sum` is now checked during installer preflight. This detects corruption but is not a signature or automatic rollback; older snapshots have no hashes.
- Before replacing installed files, the root installer now creates a timestamped, private pre-install snapshot of existing Disk Watch scripts and systemd units with present/absent manifests and a final completion marker. Backup errors abort installation; there is still no automatic rollback or backup pruning. No config, credentials or cursor are copied.
- Generate a portable archive SHA-256 checksum sidecar with a relative filename, allowing offline integrity verification even when the archive and checksum are moved together. The checksum is not an authenticity signature and adds no runtime dependency.
- Add a read-only, unprivileged `install.sh --preflight` command that checks required files, Bash/POSIX shell syntax and core commands before deployment. The updater invokes it after `git pull --ff-only` and before installing files; it is not a rollback mechanism.
- Add an offline, allowlist-based portable source archive builder (`scripts/build-portable.sh`), without Git, root, systemd or new runtime dependencies.
- Add portable one-shot `check` command (alias of `scan`) and CLI `--config`/`--state-dir` overrides with environment-variable fallbacks. This does not require installation or a systemd timer when the invoking user can read the kernel journal.

### Fixed
- Refuse hardlinked `snapshots.tsv` and `.snapshots.lock` targets during explicit SMART refresh (#21 partial), in addition to symlinks (including dangling links) and non-regular files. Validate before probing and again before append/under lock; offline mocks assert no SMART calls and unchanged linked target bytes. GNU `stat` (coreutils) is now needed for opt-in refresh only; cached reports and existing histories are unchanged. This is best-effort, not race-proof, and does not implement retention or complete stable-ID history.
- Reject existing SMART snapshot rows with malformed UTC timestamps, invalid Gregorian dates (including non-leap February 29) or out-of-range clock values before any opt-in SMART probe and under the append lock (#21 partial). Offline mocks assert zero probes and unchanged invalid histories, plus acceptance of a valid leap day. Existing valid history and cached reads remain unchanged; Bash/awk prerequisites are unchanged, and this does not validate metric semantics or implement retention.
- Suppress repository Git hooks during the root-run fast-forward updater pull (`core.hooksPath=/dev/null`) and configured fsmonitor commands during status/pull (`core.fsmonitor=false`) (#24 partial). Offline updater mocks assert the exact guarded Git invocations and unchanged fail-closed install ordering. Git and Bash prerequisites remain unchanged; other Git helpers/filters and actual root rollback are not covered, and no host is updated.
- Ignore all-`F` firmware serials and all-`F` 16-digit WWNs (including spaced/case-varied SMART output) as non-unique cache identifiers (#23 partial). A valid WWN still takes precedence over the explicit path when a serial is an all-`F` placeholder. Offline mock tests cover valid WWN fallback and two all-`F` WWN layouts; existing IDs are not migrated, and no SMART probes, dependencies or default polling are added.
- Refuse a manual update when `git status --porcelain` fails, or when the checkout becomes dirty during `git pull --ff-only` (#24 partial). Recheck after pull and before installer preflight so Git-hook/local modifications are not deployed as root. Offline mocks cover pre/post-pull status failures and a post-pull dirty tree; Git and Bash are already updater prerequisites. A rejected pull may have advanced the checkout; this is not hook isolation, automatic rollback or a production deployment.
- Treat zero-only SMART serials, `NOT SPECIFIED` and `To Be Filled By O.E.M.` as non-unique placeholders (#23 partial), using a validated WWN or the explicit path instead. Offline USB/ATA mocks also ensure a real numeric serial remains unchanged. No extra SMART calls, new dependencies, history migration, standby probing or deployment.
- Ignore non-unique placeholder SMART serials (UNKNOWN, N/A, NONE, UNAVAILABLE, NOT AVAILABLE) and all-zero WWNs as persistent cache identities (#23 partial). Prefer a validated nonzero WWN when available; otherwise use the explicit device path rather than grouping unrelated drives. Add offline USB/ATA mock regressions; no extra probes, runtime dependencies, automatic history migration or production changes. Real serial precedence and cached reads remain unchanged.
- Reject malformed existing SMART history data rows (not 13 TSV fields, empty timestamp/device/ID or missing final newline) before any opt-in SMART probe and again under the write lock (#21 partial). Preserve original history bytes and cached-read behavior; no automatic repair, schema migration, runtime dependency or deployment. Scanning all existing rows adds linear work per explicit refresh; this is not semantic validation or race-proof isolation.
- Reject an existing nonempty SMART snapshot history whose TSV header differs from the current 13-column schema or lacks a terminating newline, before any live SMART probe and again under the write lock (#21 partial). Offline mocks verify no disk access and byte-for-byte preservation of incompatible history. No automatic migration or new runtime dependency; cached reports are unchanged.
- Recognize case variants of the `Serial Number:` label in SMART text (including SCSI/USB-style `Serial number:`) and trim surrounding whitespace so an exposed serial remains the cached disk ID. Synthetic offline SCSI/USB mocks cover serial-present and serial-absent fallback without inventing unsupported metrics. This does not add WWN/by-id discovery, standby probing, new runtime dependencies, or automatic hardware access (#23 partial).
- Refuse live SMART refresh when any existing ancestor of the state/health directory is a symlink or a non-directory, even if the final state path is not itself linked. Add offline mocked regressions for nested symlink and file ancestors, checking zero SMART probes and unchanged targets. Cached reads remain unchanged; Bash-only best-effort checks do not eliminate concurrent path replacement (#21).
- Refuse live SMART snapshot refresh when the state/health directory is directly symlinked, or the snapshot/lock target is a symlink or non-regular file; validate before the SMART probe and again before writing, and open an existing regular lock without truncation. Offline tests cover symlinked directories, snapshot/lock links, FIFO locks, unchanged targets and zero hardware probes. Existing symlinked state paths must use their real path for refresh. No new runtime dependencies; best-effort checks are not race-proof and trusted parent directories are required (#21).
- Include the deployed `disk-watch-health.sh` in pre-install snapshots, strict verification, read-only recovery plans and sandbox rehearsal (#24). New snapshots use a `format.txt` schema-2 marker requiring all five installed paths in the manifests; older checksum-bearing four-path snapshots remain readable but explicitly warn that the health helper was not backed up. Add offline coverage for missing entries, legacy behavior, file contents and modes. Bash/GNU coreutils prerequisites are unchanged; no automatic rollback or production deployment.
- Refuse to publish a portable archive when a checksum command reports success but produces an empty sidecar, or when the staged checksum cannot verify the staged archive. Existing artifacts remain intact; no new build or runtime dependencies.
- Stage portable archive and checksum in a private temporary output directory, preserving existing artifacts if compression or hashing fails; add offline failure-injection regression. The final two renames are not an atomic pair; `mv` is build-only and runtime requirements are unchanged.
- Reject pre-install backup source files reached through symlinked parent directories (including nested descendants), not just symlinked leaf files; offline regression verifies no manifests or partial backup are written. Uses existing `dirname`; this is a best-effort check, not race-proof, and does not change installed files or runtime dependencies.
- Refuse existing non-regular portable archive/checksum outputs (including FIFOs) and hard links to allowlisted source files or the builder before writing. Prevents blocked builds and accidental source truncation; the preflight is not race-proof and adds no runtime dependency.
- Refuse pre-existing symlinks at either portable archive or `.sha256` output path before writing, avoiding accidental clobbering of symlink targets. Use a trusted output directory; this best-effort check does not eliminate concurrent path-replacement races. No new build or runtime dependency.
- Reject symlinked allowlisted files and a symlinked `docs/` parent when building the portable archive, before creating output, so links cannot dereference private content from outside the source tree. Offline fixture tests cover both cases; build/runtime dependencies are unchanged.
- Reject duplicate input source paths before creating pre-install snapshot manifests; previously a repeated path could yield a `.complete` snapshot that the strict verifier would reject. No runtime dependencies or live-host changes.
- Clean up only allowlisted files and empty directories created by a failed offline restore rehearsal, instead of leaving misleading partial sandbox output. Cleanup is best-effort and never touches the source snapshot or installed paths.
- Fail read-only installer preflight if the snapshot verifier, restore planner or sandbox rehearsal helper is missing, empty or Bash-syntax-invalid; this does not prove root-level recovery or change installed files.
- Reject unlisted snapshot files, hidden entries, symlinks and special files during read-only recovery verification; only four fixed installed paths and metadata files are eligible. No live paths or services are touched.
- Reject offline restore rehearsal destinations nested inside the source snapshot (including symlinked parent aliases) before any copy, preserving backup isolation without adding dependencies or touching live paths.
- Reject pre-install snapshot destinations that are not owned by the invoking user, not mode `700`, or not empty (including hidden files), before writing manifests or copies. This adds no new runtime dependency beyond the already required GNU `stat` and does not provide automatic rollback.
- Refuse root installation when `/etc/disk-watch.conf` is a symlink, not root-owned or group/world-accessible; the guard checks metadata before snapshots or replacement, without reading secrets or modifying permissions. Existing `640` configs need manual tightening; no new service or database.
- Reject duplicate active `ExecStart=` and timer `Unit=` directives in installer preflight, preventing a valid-looking entry from masking a later conflicting directive; no new runtime dependency.
- Reject a syntactically valid but misdirected `disk-watch-smart.sh` during read-only installer preflight, preventing silent loss of `smartd` forwarding after an update; add an offline regression without new runtime dependencies.
- Make installer preflight reject missing or syntactically invalid `update.sh` before replacing installed files; this does not add runtime dependencies or provide automatic rollback.
- Reject packaged systemd units whose service `ExecStart` or timer `Unit` no longer points to the installed Disk Watch entry points during read-only preflight; no extra runtime dependency or systemctl invocation.
- Avoid creating or requiring a writable state directory for notification-only `test` and `smart` commands in portable mode; add an offline regression test.
- Return a clear diagnostic when the kernel journal cannot be read rather than exposing only a raw journalctl failure.
- Avoid changing the permissions of pre-existing state directories; use a private umask for new cursor and lock files.
- Avoid exposing the Telegram bot token in `curl` command-line arguments by passing the URL via stdin; reject malformed token values before invoking curl.
- Treat local syslog logging failures as non-fatal after successful I/O alert delivery, so the journal cursor advances and the same event is not resent solely because `logger` failed.
